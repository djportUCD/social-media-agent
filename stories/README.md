# Story Intake Cache

This folder is the local handoff point between the business story discovery system and the rest of the social media agent.

- `cache/*.json` is generated by `yarn stories:refresh`.
- `feedback/*.json` stores persistent accept/reject decisions and optional reasons for why a story was not relevant.
- Each cache file contains the filtered story links for one business plugin.
- The `business_stories` curate-data source reads from here if live refresh fails or if `BUSINESS_STORY_CACHE_ONLY=true`.

Review workflow:

- Use `yarn stories:list --business <id>` to inspect the current ranked list.
- Use `yarn stories:review --business <id>` or `yarn stories:list --business <id> --interactive` for a guided accept/reject/skip loop.
- Use `yarn stories:pick --business <id> --accept 1,2 --accept-reason "great translational fit" --reject 3 --reject-reason "too operational"` for fast batch triage.
- Use `yarn stories:feedback --business <id> --index <n> --decision accept --accept-reason "good fit for our audience"` to reinforce a good pick.
- Use `yarn stories:feedback --business <id> --index <n> --decision reject --reason "..."` to record why a story is not relevant.
- Accepted stories are pinned to the front of the business story cache for curate-data and supervisor runs, so the stories you pick are preferred automatically.
- When a report comes from a manually accepted business story, that source context and acceptance reason are exposed downstream and included in Slack run summaries.
- Feedback is persisted and applied to future refreshes so the ranking learns your preferences over time.

The implementation intentionally lives inside this repo instead of vendoring a separate news agent so upstream merges stay manageable.
